# BoT-SORT 可行性探针（2026-09-21）

[English](README.en.md)。分层：单 Tracking SDK 研究；状态：本地可行性评估完成，尚未接入第四算法。

结论：相机运动补偿（CMC）有继续实现的价值，优先设计**调用者提供运动矩阵的同包 CPU 核心**，随后单独评估浏览器图像估计模块。固定七段序列合计 IDF1 提高 6.2928 个百分点、IDSW 从 1101 降至 519；MOT17-09 退步，估计成本明显，不能替换默认策略或直接宣布完整 BoT-SORT 可用。现有公开版本仍是 `0.2.0-rc.0`（npm `next`），稳定 `latest` 为 `0.1.0`。

## 实际实现范围与数学差异

这是复用本项目内核的**一次性探针**。`src`、生产 `dist`、包版本、manifest、模型注册和 Demo 未改动。结果中的 `algorithm` 仍为 `bytetrack`，配置区别只能按 `run-summary.json` 的研究配置解释，不是新增的公开算法 ID。

- CMC：OpenCV 4.10.0、单线程、固定随机种子，原图最大宽缩至 640，ORB 1500 点、Hamming KNN ratio 0.75、RANSAC 部分仿射。前/当前帧检测矩形排除前景；支持数、内点比例及 4×4 背景覆盖门槛见协议和[探针](probe/motion.py)。低支持等失败显式返回恒等矩阵并记录原因。5309 个帧间转换中成功估计 5270 个，39 个低支持回退（均在 05，约 0.735%），另有 7 个首帧。
- 矩阵方向是**上一已处理帧 → 当前帧**，原图零基坐标，行序 `[a,b,tx,c,d,ty]`。缩图恢复采用 `S⁻¹ M S` / `S⁻¹ t`，包含缩放尺寸取整产生的横纵差异。估计接受缩放 0.8–1.25、旋转绝对值 ≤15°、平移 ≤缩图对角线的 25%。
- 预测后补偿、关联前使用：状态为 `[cx,cy,w,h,vx,vy,vw,vh]`。中心/位置速度用 `M`，宽高/尺寸速度用 `abs(M)`，`J = diag(M,abs(M),M,abs(M))`，协方差为 `J P Jᵀ`。这是轴对齐框四角包络的独立推导；与论文对宽高也采用带符号 `M` 的近似不同。20×100 的框即使旋转 15°，带符号近似也会产生负宽。探针保持正包络，但反复包络可能放大框，尚未证明为最佳模型；未计入估计矩阵自身的不确定性。
- 外观沿用已归档 `pplcnet-reid-fp32@0.1.0` / WebGPU / 512 维向量，不重新推理。高分检测、原 IoU ≥0.5 且 cosine distance ≤0.25 才参与融合，代价取 `min(1-IoU, cosine/2)`；高分匹配更新归一化 EMA，alpha=0.9，初始轨迹以首个向量建库。包含 tentative 关联阶段。边界使用 ≥/≤，与论文严格 >/< 不完全相同。
- 沿用现有秒级时间、固定滤波噪声、生命周期、类别、低分续接和匹配门槛；未实施论文完整的尺寸相关噪声、检测分数融合和离线插值，也没有采用官方 C++ VideoStab。不能称作官方 BoT-SORT 复现，不能将融合结果与旧 DeepSORT 的差异全部归因于 ReID 模型。

## 时间成本与验证边界

Windows 11 / i5-10400F / Node 24.16.0 / Chromium 153.0.8010.12；Python 3.11.15、NumPy 1.23.5、SciPy 1.10.1、OpenCV 4.10.0。完整环境见来源记录。

| 测量范围 | base | cmc | cmc-reid |
| --- | ---: | ---: | ---: |
| Node 全 5316 帧跟踪累计 | 10067.14 ms | 10304.92 ms | 12986.26 ms |
| Chromium 05 全 837 帧跟踪累计 | 583.60 ms | 607.20 ms | 738.10 ms |

跟踪累计仅含输入校验、预测、补偿、关联及更新，**不含**运动估计、ReID 提取、检测器、图像解码、传输、渲染和评分。单次测量，不据小差值声称稳定加速或实际 FPS。

Python 全序列运动估计累计 239277.98 ms；每段 `estimateMs` 中位数 34.16–47.80 ms，包括当前帧 ORB、匹配、RANSAC 与原图矩阵恢复。另有读取/校验 5480.85 ms、解码/缩放 43961.51 ms，三者总计 288720.34 ms。[运动摘要](motion-summary.json)保留逐段 p50/p95。这些是离线 Python 成本，不是浏览器图像估计、模型推理或视频端到端速度。

- 全七段恒等补偿逐帧非耗时输出与原 ByteTrack 一致，七份基线 MOT SHA256 与历史完全一致；三配置均零容量丢弃。完整 Node 运行一次，没有声称全量两次重复。
- [浏览器回执](browser-result.json)：05 全 837 帧的三配置 MOT 与全部非耗时输出哈希均与 Node 一致，无 pageerror。只验证浏览器 CPU 关联及矩阵应用；矩阵在 Python 预生成，向量来自旧归档，未验证浏览器图像运动估计、ORT 推理、手机或摄像头。
- 数学和集成测试覆盖恒等、平移、旋转包络、缩放协方差、二次型、奇异/非有限矩阵、突然平移保留 ID、有轨迹时无效矩阵不推进、reset/dispose；已知平移合成图估计和全黑回退通过。不是完整生产输入验收，尤其首帧空状态下矩阵校验尚不充分。
- [日志](logs/)保留失败和成功：首次数学测试因缺模块失败；首次全量运行因历史字段名错误中止，修正读取后使用新 run-2；首次评分因 Windows 默认 GBK 解码失败，修正 UTF-8 后成功。未改实验参数或删除失败记录。

## 三条路径与下一阶段

| 路径 | 作用与代价 | 决策 |
| --- | --- | --- |
| 调用者提供矩阵，同包 CPU 跟踪 | 复用矩阵和外部检测；默认入口无图像引擎依赖，宿主负责估计质量 | **优先**：先设计并实现可选 BoT-SORT 风格核心 |
| 同包可选图像运动估计子入口 | 能从画面产生矩阵，但增加解码、特征匹配与运行时依赖 | 后续浏览器可行性及成本验收，按需导入 |
| 跨 SDK 媒体组合模块 | 调度检测、可选 ReID、运动估计、视频/摄像头 | 等兼容契约与实际用例；门户本轮只记录路线 |

下一阶段建议输入契约（设计建议，尚非公开 API）：

1. 矩阵携带前后帧 ID 与时间戳，必须连接上一个**已成功处理**的帧和当前帧；明确原图坐标、行序、尺寸、估计来源和质量信息。丢帧时须重新估计或正确组合跨帧矩阵，不能把相邻视频帧矩阵直接套到不同处理间隔。
2. 分开表达 `estimated`、`identity`、`unavailable/failed`，不把失败伪装成静止相机。外部未知补偿明确标注，决定是否使用恒等降级；不静默切换算法。
3. 首帧、seek、reset、尺寸变化、暂停恢复、大时间间隔明确失效与复位规则；所有矩阵/向量/框输入先校验后提交状态，出错不推进时间、轨迹或代次。限制非有限、奇异、反射及超范围矩阵，不能直接把本探针的局部校验升为产品契约。
4. 固定补偿顺序、框包络与裁边层次、均值/协方差/速度语义；新增矩阵不确定性与长序列旋转反例。关联与矩阵应用计时、图像估计计时分层，不能把离线输入视为免费。
5. 外观仍为可选，沿用固定特征空间和 `./reid`；实现前先定核心设计与差异清单，再做错误原子性、旧三算法回归、Node/浏览器同输入质量验证，重点调查 09 退步。通过后再决定版本和 Demo 公开入口。

与最初规划无冲突：同任务算法继续在一个独立 Tracking SDK 中，门户负责登记/比较/跳转，Workflow 不提前建设。标准 1.3.0 的领域输入与可选模型模块能够承载后续设计，本轮不增加 schema/规则/UI 要求。

## 复核与复现

从本仓运行 `node reports/2026-09-21-botsort-feasibility/verify.mjs` 核验归档、合计、来源与浏览器对齐；加 `--local` 额外核验本机研究输入和轨迹文件哈希。`evidence.lock.json` 固定所归档文件，原始图像、检测、GT、外观向量和真实轨迹不提交。

完整重新运行需在基线提交的独立 checkout 安装锁定开发依赖，按[既有数据流程](../2026-09-21-mot-reid/README.md)准备相同输入及冻结向量；把 `probe/` 原样复制到 `.tmp/botsort-feasibility/`，把协议放入同目录。按 `build.mjs` → 数学/集成测试 → `motion.py` → `run.mjs` → `score.py` → `browser.mjs` 顺序运行。脚本保留当次本地路径及 run-2 命名，重新运行使用新 checkout/新研究目录；不得覆盖已有 motion/run-2 证据。Python 评分依赖的 TrackEval 路径需指向固定且干净的提交。确定性轨迹/矩阵数值与耗时分开比较，含时间记录的 JSONL 哈希不要求跨机器相同。

本轮交付为研究代码、数据摘要与规划，本地验证记录见 [validation.json](validation.json)。正式 npm、GitHub、模型来源及线上 Demo 未执行新发布。
