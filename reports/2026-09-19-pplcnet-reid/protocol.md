# PPLCNet ReID 本地探针协议

日期：2026-09-19。类别：单 SDK 的一次性可行性研究；脚本仅用于复现研究，不是生产 runtime。承接 DeepSORT 外部向量验收，用户已确认继续。

## 预先固定的范围与门槛

- 固定 PaddleDetection `b25522a0f4bde8c80603f3ba5e3472059972e3b5`，核对 README 与配置两个权重 URL 的实际内容。记录源文件、权重、转换模型的长度及 SHA-256。只使用已核对 Apache-2.0 文件头的模型结构和预处理，不导入上游跟踪器、关联或 Kalman 实现。
- 使用原始 Paddle 2.6.2 FP32 eval 输出为参考；导出固定单目标 NCHW `[1,3,192,64]` → `[1,512]`，不在本阶段做 FP16/量化。加载 checkpoint 必须覆盖全部模型参数，不能随机补缺失参数。
- 每个输入要求有限且非零输出；Python ORT、浏览器 WASM、浏览器 WebGPU 对原始 Paddle 的最大绝对差 `< 1e-3` 且余弦距离 `< 1e-5`。失败保留，不通过删样本或放宽门槛处理。
- 数值样本包括全黑、全白、低对比、RGB 纯色、确定性纹理和实际行人裁剪；同一 FP32 输入文件送入三个执行引擎。数值对齐与图像预处理质量是两个独立问题。
- 上游 `get_crops` 先把 HWC 变成 WHC，`preprocess_reid` 再 resize、反转通道、除以 255、按 ImageNet 均值/标准差标准化。上游部署解码得到 RGB，因此原部署路径对应“转置裁剪 + BGR”。保留该路径，以及正常朝向 RGB、正常朝向 BGR、转置 RGB 共四种对照；不根据小样本结果声称恢复了未公开的训练预处理。
- 真实图像优先使用 MOTChallenge 官方 MOT17 训练集的 `02-FRCNN` 与 `04-FRCNN` 序列。预定帧号 `[1,31,61,91,121,151]`；仅有效行人 GT（mark=1、class=1、visibility>=0.7），裁剪完整位于图内、宽>=16、高>=48。每序列帧 1 为图库，其余帧中与图库相同 ID 的行人为查询。不使用训练，不上传图片或权重。
- 真实质量只报告这个确定性小样本的余弦检索 Rank-1、同/异 ID 距离，以及距离 0.2 下的拒真/认假；不设事后“稳定”门槛，不声称跨摄像头 ReID、完整 MOT17、IDF1/MOTA 或真实跟踪提升。若数据不可用，记录原因，不能用增强同一图片冒充真实身份真值。
- 浏览器固定 ORT Web 1.27.0、WASM 单线程、basic 图优化；WebGPU 禁止 CPU EP fallback，记录实际适配器。5 次预热、30 次单目标、8/16 目标各 5 组串行推理；计时包含输出回读，不含解码、裁剪、检测、跟踪或媒体调度。
- 权重专属条款与训练数据条款分别记录。代码根许可不自动视为 checkpoint 的完整再分发授权。实际提供模型加载前先演进标准 1.2.0 的算法/模型混合声明，本轮不更改生产 manifest、API、门户 registry、Demo 或版本。
