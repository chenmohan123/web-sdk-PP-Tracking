# Performance and timings

[中文](../zh-CN/performance.md) · [Home](../../README.en.md)

All values are milliseconds measured with performance.now(), not placeholders.

| Field | Boundary |
| --- | --- |
| validationMs | update entry through input/cancellation validation |
| predictionMs | State copying, pre-removal and Kalman prediction |
| associationMs | Grouping and three association stages |
| updateMs | Correction, creation and track snapshots |
| totalMs | update entry through result construction; independently measured, not a sum |

Empty stages still have scheduling overhead. No fabricated model/download/cache timings. Cold means the first frame of a new instance; warm means reusing its state. Reset clears motion state, not the JavaScript environment.
Record input and active-state scale, initialization/reset boundaries, device, browser, runtime and date. Timings from different sizes or states are not direct speedup ratios.

Demo exports contain all five actual timings, recorded timestamps, applied options, feature space, source sequence and actual algorithm metadata for processed frames. Playback timers control presentation only; the algorithm never receives browser wall time. Synchronous main execution may block UI; AbortSignal is checked before computation only.
Imports and algorithm switches validate every frame through a temporary tracker, yielding the browser main thread every100 frames for long sequences and committing atomically only on success. A3000-frame or large-gallery input can therefore take time without corrupting the current session. Seek recomputes the prefix. SVG paths show positions from the most recent100 results; export retains all actual results from the current run.

DeepSORT `associationMs` includes appearance nearest-neighbour galleries, Mahalanobis gating, cascade matching and IoU fallback. Cost varies with track count, detection count, vector dimension and gallery capacity. It excludes ReID inference, image cropping, preprocessing and embedding generation. The optional entry reports download, cache read, integrity, session and total load times separately; extraction reports preprocessing, inference, normalization and total time. decodeMs is0 because the host decodes images. The Demo separates model extraction from CPU association; GPU model time is not GPU association, and timings from different runs cannot establish end-to-end FPS.
