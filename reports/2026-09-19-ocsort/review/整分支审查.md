### Important

**F1 / P2：显式 `algorithm: null` 静默回退 ByteTrack。**

- 位置：`S/src/tracker.ts:32`。
- 问题：`value.algorithm ?? defaults.algorithm` 在类型检查之前吞掉 `null`。因此 JSON 配置或 JavaScript 调用者显式提供非法选择器时，会成功创建 ByteTrack 实例；违反“仅两种选择器、未知算法返回 INVALID_OPTIONS、不回退”的接口约束，也与其余非法选项严格拒绝不一致。
- 小复现：对当前 `dist/index.js` 执行 `createTracker({ algorithm: null }).update({ timestampMs: 0, imageSize: { width: 10, height: 10 }, detections: [] })`，实际 `algorithm` 为 `bytetrack`；同轮 `undefined` 和 `'unknown'` 均抛 `INVALID_OPTIONS`。构建入口 SHA 与真实评测摘要相同，复现对应本次冻结实现。
- 修复：只对所决定的“缺省”情况应用默认值，保留 `null` 及其他非法类型供枚举检查拒绝；新增 null、数字、布尔、对象/数组和未知字符串的边界断言，并继续验证省略选择器默认 ByteTrack。
- `undefined` 说明：当前双语 API/算法指南明确“显式 undefined 不是缺省”，所以本报告不把其拒绝行为另列缺陷。`algorithm?` 的 TypeScript 形状允许调用方持有 undefined，确有易用性取舍；若收尾选择让它等同省略，应同时同步对应文档、测试及其与其他选项 undefined 语义的差别。F1 的必要条件是不能让 null/其他非法类型回退。
