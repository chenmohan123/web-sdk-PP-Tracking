# 浏览器运动估计实验报告

日期：2026-09-23。版本：本地 `0.2.0-rc.2`。这是 PP-Tracking 独立 `motion` 子入口的 Spike 证据，不是稳定兼容或端到端视频性能承诺。

## 范围

- 输入：固定 seed `20260923` 生成的 320×180、640×360 RGBA 合成相邻帧。
- 场景：小/中/大平移、旋转、缩放、仿射、静止、亮度变化、局部遮挡、重复纹理、低纹理和超范围运动。
- 算法：`translation`、`sparse-flow`、`feature-match`。
- 环境：Node `v24.16.0`、Windows `win32`、CPU/main。浏览器页面另由 Chromium smoke 验证；本报告的耗时是 Node 合成基准，不能外推到手机、Worker、GPU/NPU、Safari 或 Firefox。
- 原始数据：[metrics.json](metrics.json)。脚本：`scripts/motion-benchmark.mjs`。

## 结果

| 算法 | 320×180 成功率 | 320×180 p95 | 640×360 成功率 | 640×360 p95 |
| --- | ---: | ---: | ---: | ---: |
| 纯平移 | 41.7% | 约 13.3 ms | 41.7% | 约 15.5 ms |
| 稀疏光流 | 33.3% | 约 53.7 ms | 33.3% | 约 71.8 ms |
| 特征匹配 | 41.7% | 约 201.0 ms | 41.7% | 约 191.1 ms |

成功率按每种尺寸的 12 个场景计算，包含预期失败的低纹理、重复纹理和超范围运动；失败结果均不带矩阵。三种算法都恢复了合成的小/中平移和亮度变化，静止场景在显式 `identityWhenStatic` 下返回恒等状态。稀疏光流对低置信度的超范围候选主动拒绝，纯平移和特征匹配也会拒绝周期纹理的歧义峰值。

## 裁定

当前结果不满足把自动估计接入 BoT-SORT 的条件：640×360 的三算法成功率都只有 41.7% 或更低，特征匹配 p95 约 191.1 ms，稀疏光流约 71.8 ms，且复杂运动与歧义纹理必须明确失败。纯平移速度较好，但表达能力有限，不能覆盖缩放、旋转和一般仿射变化。因此本阶段保留三算法为独立实验，不修改 BoT-SORT 默认输入，不更新 `latest`，也不把它登记为稳定兼容。

下一阶段若要自动接入，必须另写设计并重新取得批准；需要扩大合成矩阵、合法真实帧、浏览器实际耗时和跟踪框误差证据。
