# 0.2.0-rc.1 release candidate

[中文](../../zh-CN/releases/0.2.0-rc.1.md) · [Home](../../../README.en.md)

Date: 2026-09-22. `v0.2.0-rc.1` points to the SDK merge commit and is published through GitHub Release, npm `next`, and the hosted Demo; `latest` remains 0.1.0. The published tarball matches the fixed local SHA-256 and includes provenance.

## Changes and migration

`createTracker({algorithm:'botsort'})` explicitly selects BoT-SORT-style tracking. ByteTrack remains the default and the original three algorithms retain their interfaces. Every BoT-SORT frame requires increasing frameId/timestampMs and motion bound to previous/current successful frames. Caller matrices compensate predictions; optional appearance uses gates and EMA. Motion failure throws by default; only explicit identity fallback is accepted, and results retain its reason. See the [motion API](../botsort-candidate.md) for the contract and runnable example.

The existing Demo layout adds four algorithms in boxes/external-vector mode, original synthetic camera translation, explicit motion-failure policy and optional appearance settings. Versioned import/export preserves motion, algorithm and applied options. Switching, parameter application and imports validate before replacing state; failures preserve the session. Seek resets and replays from the first frame. Image mode remains PPLCNet + DeepSORT without automatic detection or motion estimation.

The root remains CPU/main, framework-neutral and dependency-free. ORT1.27.0 is an optional peer and the optional `./reid` is not loaded automatically. Weights, source revisions, hashes, preprocessing and model-license basis remain unchanged; see the [model card](../../../models/pplcnet-reid/0.1.0/README.en.md). BoT-SORT concepts follow arXiv:2206.14651; code is independently written under Apache-2.0 without copying third-party tracking implementations.

## Evidence and limitations

[Historical core validation](../../../reports/2026-09-22-botsort-core/README.en.md) used seven MOT17 training sequences/5316 frames with frozen motion matrices and vectors. Aggregate IDF1 rose from48.2922% to55.3487%, but sequence09 regressed. This is not universal superiority, official value-level reproduction, or end-to-end video speed. Public rc.1 package, Demo and parity validation are recorded separately; historical bundle hashes do not validate a new version.

Matrix uncertainty is not modeled and repeated rotation envelopes can inflate boxes. Fixed noise, width/height state and association details differ from the paper. CPU tracking timings exclude detection, image-motion estimation, ReID and rendering. Automatic browser motion estimation, video/camera scheduling, phones, Safari, Firefox, Worker and NPU are outside this delivery's compatibility claims.
