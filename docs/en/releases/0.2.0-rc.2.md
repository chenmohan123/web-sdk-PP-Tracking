# 0.2.0-rc.2 prerelease

[中文](../../zh-CN/releases/0.2.0-rc.2.md) · [Home](../../../README.en.md)

Date: 2026-09-23. `0.2.0-rc.2` shipped through an immutable tag, GitHub Release, npm Trusted Publishing, and the standalone Demo. npm `next` and the hosted Demo point to rc.2; stable `latest` remains 0.1.0. See the [release report](../../../reports/2026-09-23-release-rc2/README.md).

## Changes

- Added the independent `web-sdk-pp-tracking/motion` subpath for adjacent `ImageData`/`VideoFrame` translation, sparse-flow, and feature-matching experiments.
- Added `/motion.html`, JSON export, reset, and a fixed-seed synthetic benchmark. It does not read detections, load models, or automatically connect to BoT-SORT.
- Quality failures return a matrix-free `failed` result; structural input errors throw `MotionEstimateError`. Sparse flow uses a conservative `0.8` confidence gate, while periodic texture and out-of-range candidates fail explicitly.

## Evidence and limits

The synthetic benchmark on Windows 11, Node 24.16, Chromium 153, CPU/main is recorded in the [motion estimation report](../../../reports/2026-09-23-motion-estimation/README.en.md). At 640×360, Node p95 is 15.5 ms for translation, 71.8 ms for sparse flow, and 191.1 ms for feature matching; success rates are 41.7%, 33.3%, and 41.7%. These rates include expected failures for complex motion, low texture, repeated texture, and out-of-range motion. They do not generalize to phones, workers, GPU/NPU, Safari, Firefox, video, or camera scheduling.

BoT-SORT, the ByteTrack default, the ReID subpath, and hosted version boundaries are unchanged. Automatic BoT-SORT integration requires a separate design plus legal real frames, browser timings, and tracking-box error evidence.
