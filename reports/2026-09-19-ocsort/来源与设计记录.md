# OC-SORT 来源与设计记录

日期：2026-09-19。任务：PP-Tracking Task 1。实现：`codex/tracking-algorithms`。

## 固定来源

- 论文：Jinkun Cao、Jiangmiao Pang、Xinshuo Weng、Rawal Khirodkar、Kris Kitani，
  *Observation-Centric SORT: Rethinking SORT for Robust Multi-Object Tracking*，
  arXiv `2203.14360v3`，更新时间 2023-03-16，CVPR 2023 接收版，
  <https://arxiv.org/abs/2203.14360>。
- 论文摘要固定语义：标准 KF 在遮挡期间累积误差；OC-SORT 用检测观测构造遮挡期
  虚拟轨迹修正滤波参数，仍为在线实时的框输入跟踪器。
- 公开来源：<https://github.com/noahcao/OC_SORT> 的 README 与 LICENSE，读取时
  `master` 提交 `8462e7e729a93ccd3bd995c0a79a890336cb3a0b`，仓库声明 MIT。
  本实现未读取或翻译该仓库的 Kalman、SORT 或跟踪源码，也未复制代码。

## 数学落地

论文第 4.1 节定义 ORU：取丢失前最后观测 `z_last` 与重新关联的观测 `z_now`，
生成 `z~(t)` 线性虚拟轨迹；每个缺失时刻执行 predict/re-update，重新关联后再
继续正常 KF。实现从最后真实观测后的八维滤波快照恢复，缺失时间来自调用者实际
提交的成功帧，按顺序逐次重放。虚拟框不写入真实历史、不增加 `hits` 或 `score`，
当前真实观测只校正并计数一次。

论文第 4.2 节定义 OCM：关联代价为 `-IoU + lambda * DeltaTheta`，其中方向由
观测中心差计算，论文实现使用三帧间隔和 `lambda=0.2`。SDK 以最大化形式使用
`IoU - ocmWeight * DeltaTheta / pi`，先强制原始 IoU 门限和类别门限，再比较
方向分数；零位移不产生方向惩罚。

论文第 4.2 节还定义 OCR：常规关联后，用未匹配轨迹的最后观测对剩余观测发起第二
轮关联。SDK 只对高分检测执行该轮，沿用类别和 IoU 硬门限，不引入 ByteTrack 的
低分续接。

## 参数和边界

| 参数 | 默认值 | 有效范围 | 作用 |
| --- | ---: | ---: | --- |
| `ocmWeight` | `0.2` | `[0,1]` | 方向差权重 |
| `ocmDeltaMs` | `300` | `[1,10000]` | 方向历史最小毫秒间隔 |
| `ocmHistoryLength` | `30` | `[2,120]` | 真实观测历史容量 |
| `oruMaxReplaySteps` | `30` | `[1,60]` | 缺失成功帧的最大重放次数 |

OC-SORT 的专属参数只接受 `algorithm: 'ocsort'`；ByteTrack 的
`lowScoreThreshold`、`lowMatchIouThreshold` 只接受 `algorithm: 'bytetrack'`。
OC-SORT 仍使用高分阈值、建轨阈值、IoU 门限、生命周期和容量参数。真实观测
历史超过容量时只裁剪最旧观测；缺失重放时间戳超过上限时才在当前事务
中结束轨迹，避免无界循环。大间隔、超时、输入错误、数值错误、预取消均在提交
前处理；失败不推进时间、ID、滤波状态或历史。

## 实现边界

本项目复用已有独立八维 `cx/cy/w/h` 恒速 Kalman、秒级时间戳、类别隔离、状态
生命周期和事务提交。论文代码的七维状态、帧间隔、具体噪声和实现细节没有被移植，
因此只声明机制对应关系，不承诺官方逐值兼容、复现论文速度或真实 MOT 精度。
