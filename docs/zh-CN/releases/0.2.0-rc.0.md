## 从0.1迁移

`createTracker()`继续默认ByteTrack CPU/main；原有update/reset/dispose及框输入不变。`algorithm: 'ocsort'`显式启用OC-SORT；`algorithm: 'deepsort'`要求一致的FeatureSpace及逐帧、逐检测外观向量。可选`web-sdk-pp-tracking/reid`从调用者提供的人体图像与框生成512维向量，不提供检测器或视频/摄像头调度。切换模型、特征空间、来源或后端须释放会话并复位依赖的跟踪状态；轨迹ID不是人的身份。

算法依据ByteTrack、OC-SORT、Deep SORT论文独立实现，代码Apache-2.0；噪声、毫秒生命周期及宽高状态与论文实现有差异，详见[算法说明](../algorithm.md)和NOTICE，不声明官方移植或逐值兼容。

## 安装与模型

安装指定 RC；也可消费源码生成的 tarball：

```sh
npm install web-sdk-pp-tracking@0.2.0-rc.0
# 仅使用可选模型子入口时安装：
npm install onnxruntime-web@1.27.0
```

根入口无生产依赖，ORT1.27.0仍为可选peer；显式导入`./reid`后也只在load时加载引擎。关联始终CPU/main；特征提取单独选择WASM/main或WebGPU/main，不静默回退。算法五项耗时和模型下载、校验、会话、解码、预处理、推理、后处理耗时分别报告；两层totalMs独立测量。

模型仍为`pplcnet-reid-fp32` 0.1.0，FP32/ONNX opset17，33,704,835字节，SHA-256 `24d347f47405bb1bd24fd582783507edbcb16571d2e845d0528b0ad7856336e4`。默认ModelScope revision `dc3d9f7a97be4033e654525f0e9d3fbd5eaf7c9b`，可选Hugging Face revision `02c299b5b5618315fc754002b7ea7c95c95e8a82`；来源失败不自动换源。权重不进入npm。许可采用官方仓库Apache-2.0作为转换分发依据，专属权重授权与训练数据披露范围见[模型卡](../../../models/pplcnet-reid/0.1.0/README.md)。

## 证据与限制

[2026-09-21真实评测](../../../reports/2026-09-21-mot-reid/README.md)属于0.2.0-alpha.0实测提交0194ea5：七段5316帧/67639检测，ByteTrack、OC-SORT、DeepSORT+PPLCNet IDF1分别48.2922%、48.4107%、45.4637%。DeepSORT的其他局部指标不构成总体提升；无禁用外观消融，不能单独归因模型。ByteTrack保留默认，ReID仅为人体实验能力。这不是测试集排名、手机性能或端到端视频速度。

RC对生产运行时代码仅更新版本字符串与类型字面量，数学、权重、预处理、阈值与接口语义不变；历史报告和hash保持原样，未重跑全5316帧。RC须以本轮实际tarball和浏览器证据验证，不能将历史构建hash充作RC测量。当前验证环境与日期见[兼容性](../compatibility.md)；390px为桌面视口，Safari、Firefox、手机真机、Worker和NPU未验证。Demo分别提供状态复位、取消与模型清理，语言切换保留状态。
