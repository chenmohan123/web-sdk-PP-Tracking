# MOT17 real detection sequence evaluation — 2026-09-19

[中文 and per-sequence table](README.md) · [Full summary](summary.json) · [Sources and citations](sources.json) · [Reproduction CLI](../../scripts/evaluation/mot17/README.en.md)

All seven MOT17 FRCNN **training** sequences were fixed before evaluation: 02/04/05/09/10/11/13, 5316 frames and 67639 public detections. Default parameters were not tuned on these sequences. This evaluates an independent SDK consuming existing detections, not the MOT17 test leaderboard, official ByteTrack accuracy, video pipeline speed, or cross-device support.

| low=high ablation | 48.3465 | 1066 | 44.3405 | 3785 | 57653 |

The ablation changes only lowScoreThreshold from 0.1 to highScoreThreshold=0.5. Low-score association removes 487 false negatives but adds 384 false positives and 35 switches; MOTA rises by 0.0606 percentage points while IDF1 falls by 0.0543 points. It is not an unconditional accuracy improvement. Sequences 10/13 contribute 799 of the 1101 default switches. No ReID, camera-motion compensation, or reliable recovery of identity through occlusion is claimed.

Unmodified MIT TrackEval commit `12c8791b303e0a0b50f753af204249e622d0281a` supplies MotChallenge2DBox preprocessing (DO_PREPROC=true, pedestrian) and Identity/CLEAR at IoU 0.5. The official combine_sequences methods compute totals; the evaluated GT count is 112297. Only observed, confirmed tracks are exported. No custom switch counter, tentative/lost predictions, or mean of sequence percentages is used. Python 3.11.15, NumPy 1.23.5 and SciPy 1.10.1 are recorded along with loaded scorer source hashes, its LICENSE hash, dataset/input/output hashes and all options. Only the required official modules are imported to avoid unrelated datasets and plotting dependencies; scoring code is unchanged.

MOT timestamps use frame*1000/fps. One-based pixel origins become zero-based SDK coordinates and are restored on output. The adapter preserves empty frames and low scores, clips boxes, drops empty intersections, and rejects malformed rows instead of truncating. GT never enters the SDK. Actual sequences needed no geometric clipping or empty removal; 378 boundary boxes needed an inward machine-precision adjustment to satisfy the strict floating-point bounds. A new regression test covers this adapter-only fix.
